## 1. Estrategia

Pirámide de la skill `testing-strategy`: muchas unitarias, algunas de integración con API, pocas E2E.

| Nivel                | Herramienta                          | Qué cubre                                                                                       | BD                                                          |
| -------------------- | ------------------------------------ | ----------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| Unitaria backend     | Vitest                               | Motor de cálculo (`pricing-engine`), utilidades, servicios con doble de Prisma, datos del seed  | No                                                          |
| API backend          | Vitest + Supertest                   | Rutas, Zod, roles, formato de error (servicios simulados) y flujos HTTP con servicios reales    | No (doble en memoria `tests/helpers/fakeDb.js`)             |
| Integración backend  | Vitest + Supertest + PostgreSQL real | Concurrencia de stock, secuencia diaria, CHECK, flujos completos de los criterios 1-3           | **Solo esquema `test`** vía `DATABASE_URL_TEST` (se omite si falta) |
| Unitaria/widget UI   | `flutter_test`                       | Modelos, controladores, interceptor, 13 pantallas, accesibilidad, atajos                        | Repositorios falsos                                         |
| Flujo UI             | `flutter_test`                       | Recorridos completos cliente y administrador                                                    | Repositorios falsos                                         |
| E2E de escritorio    | `integration_test` (`-d windows`)    | La app Windows compilada, con ventana y motor de render reales                                  | Repositorios falsos (sin red)                               |

Reglas respetadas: no se lee `backend/.env.local`; la base `pizzeria` esquema `public` no se escribe; en este entorno `DATABASE_URL_TEST` **no existe**, por lo que las 22 pruebas de integración con BD real se omiten (no se derivó la URL).

Convención de IDs: `UT-Bxx`/`IT-Bxx` (fase 2/4), `WT-xx` (fase 3/5), `QA-xx` (nuevos de esta fase backend), `QA-Fxx` (flujos Flutter nuevos), `IT-F01` (integration_test).

Casos obligatorios por historia (camino feliz, validación, no autenticado, no autorizado, no encontrado, concurrencia): las celdas vacías o parciales están en la sección 5 (huecos).
